# uYao 問藥 Agent 規範

本版定位為免會員的目錄查詢與藥局聯絡助手。先驗證使用者是否能從詢問走到藥師確認與到店，不建立長期個人健康檔案。以下是產品與實作邊界，不是法律意見或合規認證。

## 對話順序

1. 在聊天內先問是否有已知藥物、食物或其他過敏；沒有預選答案，不跳 modal。有過敏須填已知過敏原，不確定可直接找藥師。完成回答不等於適用性評估或個資分享同意。
2. 接受品名、成分或症狀文字。品名／成分僅查可核對來源的目錄；症狀及個人化用藥問題轉介藥師或醫師，不由症狀生成商品推薦。
3. 僅提供來源與藥局聯絡選項。藥品適用性、合法供應、實際庫存與到店安排由藥師／藥局確認。是否完成取藥必須另有真實證據。
4. 代表性緊急警訊立即提供就醫／119 提醒，不等待過敏步驟或模型。此功能不是完整急症分級服務。

## 不允許的行為

- 診斷、開方、個人化選藥／保健品治療推薦、決定劑量、停藥或換藥。
- 以療效保證、療效比較、症狀對應商品等方式促銷；製作藥品廣告或處方藥導購。
- 替使用者下單、收款、安排藥品配送／代購，或自動建立預留、通知藥局。
- 捏造台灣藥證、核准適應症、庫存、價格、藥師認可或成功取藥紀錄。
- 主動要求姓名、身分證、健保、病歷、處方、聯絡資料以建立健康檔案。無關聊天回到查詢範圍。

## 實際防線與限制

伺服器先檢查最多八則 user 歷史。只有完整對上既有品名、別名、成分或目錄詞（加上有限查詢用語），或固定的第幾項續問，才允許進入工具流程。不能辨識為這些查詢的自由文字直接回固定範圍／專業轉介提醒，不靠模型自行判斷是否可放行。超過 600 字元的訊息拒絕處理，避免截掉句尾的症狀或限制。

模型查詢只能使用伺服器核對出的原始目錄詞；不能翻譯擴詞或改查其他品項。續問只發給模型使用者指定的那一項，不能只因 client 傳入有效 slug 就取得其他品項的呈現權。只有明確的藥局續問可呈現藥局聯絡資料。模型自由文字永遠不顯示，卡片比對理由不引用長篇保養／療效敘述，也不把這些敘述送進工具結果。非緊急的症狀分流只給固定專業轉介，不提供未經審閱的處置或劑量指示。

Agent 目前僅呈現目錄分類為「非藥品」的品項。藥品與「待確認」分類不出現在 Agent 商品／藥局卡片中；這是本產品的保守範圍，不是宣稱台灣全面禁止藥品資訊查詢，也不是替現有分類背書。部分原本有結果的查詢（如益生菌、維生素C、葉黃素）暫時沒有可呈現結果，須先完成資料分類確認。不得為了恢復結果而無依據地修改分類。

模型故障走相同限制的目錄降級路徑。固定查詢文法會拒絕部分正常自然語句，急症識別仍非完整分級；目錄資料和實際營運仍需審核。不能用通過測試宣稱醫療安全或全面守法。

過敏表單留在分頁暫存，30 分鐘後需重新確認，不送入模型。原始對話在 uYao 伺服器檢查，不轉送外部 AI；供應商只收到核對後的公開目錄詞、伺服器產生的動作指令、服務區與所需的公開品項資料。這不代表所有伺服器／託管紀錄均不留存，請勿輸入身分與病歷。藥局需求表單另行核對及確認後才送出。`store: false` 不等於供應商零保留。加入會員、永久記憶、真實健康紀錄或其他資料用途前，須另行設計必要性、有效同意、告知、保存／刪除與存取權限。

費用沿用每 IP 每小時 20 次、每請求最多 4 輪、每輪 1200 output tokens 的限制，無自動重試；這不是全站硬性支出上限。Production 的限流 KV 不可用時停止 Agent。模型費用與餘額由供應商帳號控制。

## 台灣法規檢視依據

- [藥事法](https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=L0030001)：第 24、65–67 條涉及藥物廣告定義、刊播資格、事前核准與處方藥廣告限制。AI 回覆結合品牌、療效及購買動線仍須依實際內容檢視，不能以「聊天」或免責聲明排除適用。
- [食藥署藥物廣告說明](https://www.fda.gov.tw/tc/siteListContent.aspx?id=2206&sid=1710)：目錄來源可追溯不等於文案已合法核准；新增藥品、療效文案、廣告或交易流程須另行審查。
- [醫師法第 28 條](https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=L0020001)：未取得合法醫師資格執行醫療業務涉及資格限制與法定例外；AI 服務是否涉及醫療業務仍須按實際內容判斷。本產品排除個別診斷與治療決定。
- [食藥署食品廣告規範說明](https://www.fda.gov.tw/TC/siteContent.aspx?sid=12345)：食安法第 28 條禁止不實、誇張或易生誤解及醫療效能之標示、宣傳或廣告。食品／保健品也不能作為症狀治療推薦的替代出口。
- [個人資料保護法](https://law.pdpc.gov.tw/LawContent.aspx?id=FL010627)：健康相關內容依實際資料性質檢視第 6 條等規範與告知義務。沒有會員不代表沒有個資處理。

本次對照公開條文與主管機關說明（2026-09-06），不把尚未施行的修法當作現行要求。公開上線前仍須針對實際目錄、文案、資料流、供應商條款及藥局營運方式，由台灣法律與藥事專業人員確認；本版沒有完成該項認證。

## 法規到實作的核對

| 風險 | 此版限制 | 驗證 |
|---|---|---|
| 症狀導購、角色扮演開方、隱藏字元繞過 | 不明意圖不進模型；固定專業轉介 | boundary tests 的中英文與隱藏字元案例 |
| 模型改查其他商品、借用畫面上其他品項 | 原查詢限制、指定續問、伺服器 ID 權限 | 惡意 tool caller 與未選取品項案例 |
| 食品療效暗示、未確認分類展示 | 不回傳長篇比對描述；只展示非藥品分類 | 全目錄後綴測試、分類排除與英文正向查詢 |
| 假冒 assistant 歷史、使用者自行貼入病歷 | 不轉送原始對話；未知文字攔截 | provider payload 與 JSON／NDJSON route tests |
| 截斷句尾安全資訊 | 超長輸入回 422 | API 長訊息回歸案例 |

這些測試證明程式限制，不能證明廣告資格、內容核准、品項分類或個資處理已獲主管機關認可。PR 保持草稿，正式上線前仍需完成實際服務的法律／藥事審查；本次不啟用新資料用途或修改正式環境設定。
