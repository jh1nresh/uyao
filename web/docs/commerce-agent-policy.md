# uYao 問藥 Agent 規範

本版定位為免會員的目錄查詢與藥局聯絡助手。先驗證使用者是否能從詢問走到藥師確認與到店，不建立長期個人健康檔案。以下是產品與實作邊界，不是法律意見或合規認證。

## 對話順序

1. 在聊天內先問是否有已知藥物、食物或其他過敏；沒有預選答案，不跳 modal。有過敏須填已知過敏原，不確定可直接找藥師。完成回答不等於適用性評估或個資分享同意。
2. 接受品名、成分或症狀文字。品名／成分僅查可核對來源的目錄；症狀及個人化用藥問題轉介藥師或醫師，不由症狀生成商品推薦。
3. 僅提供來源與藥局聯絡選項。藥品適用性、合法供應、實際庫存與到店安排由藥師／藥局確認。是否完成取藥必須另有真實證據。
4. 代表性緊急警訊立即提供就醫／119 提醒，不等待過敏步驟或模型。此功能不是完整急症分級服務。

## 不允許的行為

- 診斷、開方、個人化選藥／保健品治療推薦、決定劑量、停藥或換藥。
- 以療效保證、療效比較、症狀對應商品等方式促銷；製作藥品廣告或處方藥導購。
- 替使用者下單、收款、安排藥品配送／代購，或自動建立預留、通知藥局。
- 捏造台灣藥證、核准適應症、庫存、價格、藥師認可或成功取藥紀錄。
- 主動要求姓名、身分證、健保、病歷、處方、聯絡資料以建立健康檔案。無關聊天回到查詢範圍。

## 實際防線與限制

系統提示詞限制模型用途；伺服器先檢查送入的 user 歷史，再允許有限只讀工具。模型自由文字不顯示，商品 ID 必須來自伺服器目錄或驗證過的畫面狀態；安全提醒由伺服器固定文字輸出。模型故障降級為目錄查詢。關鍵字路由、模型意圖判讀、八則歷史上限都可能漏判；不能用測試通過宣稱醫療安全或全面守法。

過敏表單留在分頁暫存，30 分鐘後需重新確認，不送入模型。聊天文字可能含使用者自行提供的健康資訊，因此頁面明確告知外部 AI 處理，並請勿輸入身分與病歷。藥局需求表單另行核對及確認後才送出。`store: false` 不等於供應商零保留。加入會員、永久記憶、真實健康紀錄或其他資料用途前，須另行設計必要性、有效同意、告知、保存／刪除與存取權限。

費用沿用每 IP 每小時 20 次、每請求最多 4 輪、每輪 1200 output tokens 的限制，無自動重試；這不是全站硬性支出上限。Production 的限流 KV 不可用時停止 Agent。模型費用與餘額由供應商帳號控制。

## 台灣法規檢視依據

- [藥事法](https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=L0030001)：第 24、65–67 條涉及藥物廣告定義、刊播資格、事前核准與處方藥廣告限制。AI 回覆結合品牌、療效及購買動線仍須依實際內容檢視，不能以「聊天」或免責聲明排除適用。
- [食藥署藥物廣告說明](https://www.fda.gov.tw/tc/siteListContent.aspx?id=2206&sid=1710)：目錄來源可追溯不等於文案已合法核准；新增藥品、療效文案、廣告或交易流程須另行審查。
- [衛福部醫師法資訊](https://www.mohw.gov.tw/cp-7175-83366-1.html)：個別診療行為須檢視醫事專業資格與實際服務方式，不能用「AI」稱呼取代醫療專業責任。
- [個人資料保護法](https://law.pdpc.gov.tw/LawContent.aspx?id=FL010627)：健康相關內容依實際資料性質檢視第 6 條等規範與告知義務。沒有會員不代表沒有個資處理。
