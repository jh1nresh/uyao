# Spec：品項實拍修正

> Status: implemented（部分）· 2026-08-18
> Scope: `web/public/products/*.webp` 三張已上線的合作藥局實拍。修正既有缺陷、定義重拍門檻與拍攝規格。
> 前置：`web/lib/types.ts` 的 `DrugImage`、`web/lib/drug-image.test.ts`
> 不在範圍：目錄擴充、庫存、`OFFERS`、品項頁版面、生成插畫路線

## 為什麼現在做

站上目前只有一銘藥局的三個品項有圖，全部標記 `kind: "packshot"`。三張都已去背並壓到
45–68 KB，效能與版位沒有問題。**問題在攝影本身**，而攝影缺陷無法用壓縮或去背補救。

品項圖在這個產品裡的工作只有一件：

> 使用者在藥局現場或出門前，從清單認出「就是這個」。

不是廣告，不是原廠素材。因此判準是**可辨認**，不是好看。

## 走過的路線與現行決議

生成插畫路線已經試過並否決，不要重啟：

```text
e10ef06  match partner item packshots closer to the real packaging
d7d85f3  replace generated art with the pharmacy's real packaging photos   ← 退回實拍
85fc0da  cut the shelf background out of the partner item packshots        ← 現行
```

`.tmp/design-work/2026-08-18-partner-item-product-art/adjustment-pack.md` 是被否決的那一輪
（cream 底、`kind: "illustration"`、無文字無商標）。保留為歷史證據，不是現行方向。

**現行方向：實拍 + 修圖。** 理由是實拍能顯示真實包裝上的品名、規格與批次外觀，
生成圖不能 —— 而「認出貨架上那一盒」正需要這些。

## 硬邊界

`web/lib/types.ts` 已經寫死的宣告語意，本 spec 不放寬：

- `packshot` = 可代表實際包裝的實拍。
- `illustration` = 生成示意圖，畫面上必須標「示意圖，非實際包裝」。
- **生成圖絕不可標成 `packshot`。**

由此推導出修圖的允許範圍：

| 操作 | 允許 | 理由 |
|---|:--:|---|
| 換背景 | ✅ | 商品像素不動（現行 `packshot-cleanup.swift` 已是此作法） |
| 裁切、留邊 | ✅ | 不改變包裝內容 |
| 曝光／白平衡／對比校正 | ✅ | 還原現場光源造成的偏差 |
| 去反光（既有像素的局部減光） | ✅ | 還原被反光遮蔽的既有印刷 |
| 透視校正 | ✅ | 幾何變形，不新增內容 |
| 補 alpha 通道 | ✅ | 只影響合成方式 |
| **重繪被反光洗掉的文字** | ❌ | 憑空產生法規標示＝偽造 |
| **補回被裁掉的 logo** | ❌ | 同上 |
| **生成整張圖** | ❌ | 違反 `packshot` 宣告 |
| **修改劑量、規格、字號、廠商識別** | ❌ | 可查證的事實 |

判準一句話：**修圖只能還原照片裡已經存在的資訊，不能新增資訊。**
還原不了的，走重拍，不走生成。

## 現況缺陷

證據：`web/public/products/*.webp`（900×1125，`hasAlpha: no`）

### 共同缺陷

1. **無 alpha 通道** — 背景色是烤進 pixel 的。頁面底色一改、或未來要 dark mode，
   會露出色塊。`packshot-cleanup.swift` 目前合成到單色 `#F2EFE6` 而非輸出透明。
2. **alt 與檔案不符** — 三張 alt 都寫「已去背」，但檔案 `hasAlpha: no`。
   語意上「去背」成立（背景已換成單色），但若之後改輸出透明需同步檢查。

### 逐張

| slug | 缺陷 | 可修圖 | 判定 |
|---|---|:--:|---|
| `greenplus-elgucare` | 白罐右側過曝，罐身成分文字糊掉 | 局部減光可救部分 | **修圖** |
| `yuanding-puregps-defense-450` | 左上 `iD BioTech` 廠商 logo 被裁掉一半；盒面透視傾斜；收縮膜反光洗白「450 plus」 | 透視可校正；裁切邊界需回原圖重裁 | **回原圖重裁 + 修圖** |
| `chungchi-yiyuansu-gastrodia-100` | 瓶子倒置（畫面上半為瓶蓋底面，可見 HDPE 標誌與模具編號）；品名「憶元素」被前方盒子遮擋；塑膠膜反光糊掉盒面 | 主體姿態錯誤，無法後製修正 | **重拍** |

## 重拍門檻

符合任一條就是重拍，不要嘗試修圖：

- 主體姿態錯誤（倒置、背面朝前、被遮擋）。
- 品名或規格在原圖中就不可辨識。
- 關鍵資訊被裁切出畫面。
- 反光面積覆蓋主要識別區且無殘留印刷細節。

## 拍攝規格（交給合作藥局）

目標是**免修圖直接可用**，降低往返成本。

```text
背景    單色淺色平面（白紙／淺色桌面），不要貨架
光源    窗邊自然光或室內光，避免直射造成鏡面反光
角度    正面平視，鏡頭與盒面平行（避免梯形變形）
姿態    盒子正面朝前直立；瓶罐標籤朝前，瓶蓋朝上
構圖    主體置中，四邊各留約 15% 空白，不可裁切到任何一角
反光    有收縮膜或亮面包裝時，稍微側轉避開光源，或關閉頂燈
數量    每品項 2–3 張（正面、含側面規格標示面）
格式    手機原始畫質，不要套濾鏡、不要裁切、不要傳截圖
```

一句話版本（可直接貼給藥局）：

> 麻煩幫忙拍商品正面照：放在白紙或淺色桌面上，盒子正面朝前立好、瓶子標籤朝前瓶蓋朝上，
> 手機正對著拍，四周留點空白不要切到邊，避開燈光反光。每樣拍 2–3 張，原圖傳來就好。

## 管線

現有腳本已覆蓋去背與壓縮，缺的是校正環節：

```text
藥局原始照片
  → [新增] 曝光／白平衡／透視／去反光校正        ← 目前缺這段
  → packshot-cleanup.swift（去背 + 裁切留邊）
  → optimize-product-images.py（900px、WebP、剝 EXIF）
  → web/public/products/<slug>.webp
  → web/lib/data.ts 的 image 欄位
```

注意 `optimize-product-images.py` 已處理 EXIF 剝除 —— 商品實拍常含 GPS，
門市座標不該進版控。這條不可省略。

校正環節的實作選項（依序評估，不預設要寫新程式）：

1. macOS 內建 `sips` 的曝光／gamma 調整 —— 零相依，優先。
2. Preview.app 手動校正 —— 三張圖的量級，手動可能比寫腳本便宜。
3. 只有在品項數成長到需要重複處理時，才考慮把校正寫成腳本。

## 驗收

每張圖必須同時滿足：

**事實層**
- 品名、規格、劑型在圖上可辨識。
- 未新增原照片不存在的任何文字、標章、數字。
- 廠商識別未被裁切。

**技術層**
- 900×1125（4:5），< 200 KB（`drug-image.test.ts` 的 `MAX_BYTES`）。
- EXIF 已剝除。
- `kind: "packshot"`，且 alt 含「包裝照片」、altEn 含 `packaging photo`。

**驗證指令**
```bash
cd web
npm test                    # drug-image.test.ts：檔案存在、大小、kind 與 alt 一致性
```

```bash
# EXIF 檢查
mdls -name kMDItemLatitude web/public/products/<slug>.webp   # 應為 (null)
```

瀏覽器實跑三個品項頁與 `/store/一銘藥局`，確認清單並排時三張可互相區分。

## 不做什麼

- 不重啟生成插畫路線（已於 `d7d85f3` 否決）。
- 不因為修圖而放寬 `packshot` 宣告。
- 不重繪任何被反光或裁切損失的內容。
- 不為三張圖引入 npm 影像相依（`sharp` 等原生模組不划算，
  `optimize-product-images.py` 已明確記錄此決定）。
- 不在本 spec 範圍內處理目錄擴充或庫存。

## 待決

1. `packshot-cleanup.swift` 是否改為輸出透明 PNG（保留 alpha），
   由品項頁是否需要換底色決定。目前無此需求，暫不改。
2. 憶元素重拍需要藥局配合，時程未定。在重拍到位前，該品項維持現圖或改為無圖 ——
   `types.ts` 已寫明「沒有可用素材時就不放 —— 空著比放錯圖好」，倒置的瓶子是否
   已達「放錯圖」門檻，需要一次判斷。

## 執行結果 · 2026-08-18

實作於 `claude/product-plates`。三張都重跑過校正管線，技術層全數通過。

### 與 spec 假設不符的兩點

**1. Defense 的廠商 logo 無法用「回原圖重裁」救回**

spec 判定為「回原圖重裁 + 修圖」，前提是原圖有完整的 `iD BioTech` logo。實際檢查
`photos/defense.png`：**原圖左緣就已經把 logo 切掉一半**，盒子本身超出取景範圍。

因此依 spec 自身規則改判：

- 「補回被裁掉的 logo」= ❌ 禁止
- 重拍門檻「關鍵資訊被裁切出畫面」= 符合

→ **改判重拍**。本輪只做亮部還原（收縮膜反光覆蓋 `450 plus` 的部分已可辨讀）。
其餘識別資訊（`PUREGPS`、`強抗力優 450+`、`Defense`、`60 Capsules`、`wellmune`、
`FDA APPROVED`）原本就完整，不影響「認出這盒」的主要工作。

**2. 憶元素不必重拍，裁切即可**

spec 判定為重拍，並在待決 #2 問「倒置的瓶子是否已達放錯圖門檻」。

實際上倒置的是**瓶子**，盒子本身姿態正確且品名完整。裁掉上半部的瓶子後，
剩下的盒子正面完全滿足「認出就是這個」—— 裁切屬允許操作，不改變包裝內容。

→ **待決 #2 結案：不移除、不重拍，改為裁切至盒子。** 代價是解析度降到 529×504，
在 900px 版位上會放大約 1.5 倍，略軟但可辨識。之後若有重拍再換掉。

### 本輪實際做的事

| slug | 操作 | 結果 |
|---|---|---|
| `chungchi-yiyuansu-gastrodia-100` | `--crop` 去掉倒置瓶子 + `--highlights 0.55` | 品名完整可辨，無倒置物件 |
| `yuanding-puregps-defense-450` | `--highlights 0.5` | `450 plus` 反光部分還原 |
| `greenplus-elgucare` | `--highlights 0.6` | 罐身亮部略回收 |

管線缺的校正環節補在 `packshot-cleanup.swift`（`--crop` / `--highlights` /
`--exposure`），沒有新增腳本也沒有新增相依 —— CoreImage 是系統內建。校正一律
在去背之前執行，符合 spec 的管線順序。

### 仍未解

- Defense 廠商 logo：需重拍，已納入拍攝規格。
- 憶元素解析度偏低：需重拍才能改善。
- 待決 #1（透明 PNG）：維持不改，目前無換底色需求。
